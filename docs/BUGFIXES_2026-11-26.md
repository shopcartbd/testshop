# Bug-fix release — 26 November 2026

Scope: product-view Add to cart / Buy now, account 500s, and a whole-site sweep of slow or broken interactions.

## What was wrong

- Live product-page clicks left the button at “Adding…” for ~10–15 seconds. The cart API succeeded, but each request paid for up to 20 cross-region PostgreSQL round trips (session prune on every request, per-key settings queries, repeated cart/items/totals queries, a two-query rate limiter).
- Buy now redirected to `/cart` instead of `/checkout`.
- `shop.js` read `btn.dataset.variant` while the HTML supplies `data-variant-id`, so variant products sent an empty variant id; only the first add button was updated or disabled.
- Guest `/account/wishlist` and `/account/reviews` ran DB queries before `Auth::requireLogin()`. The wishlist path could raise a foreign-key error; reviews used PostgreSQL-invalid `SELECT DISTINCT … ORDER BY o.placed_at`.
- The cart coupon “remove” control was an anchor with `data-ajax-form`, but the JS listener only handles form `submit`.
- The newsletter error box was outside its `data-ajax-form`, so validation errors were never displayed there.
- A 419 CSRF response already carries a fresh token but the browser did not retry; there was no request timeout or optimistic cart-count feedback.

## What changed

- Added request-scope caches for settings, cart rows, cart lines and shipping rates; invalidation on every cart mutation and after checkout.
- Replaced the two-query rate limiter with one atomic `INSERT … ON CONFLICT … RETURNING`; sample session pruning instead of deleting on every request; removed a redundant first-request session UPDATE.
- `app.js` now bumps the cart count immediately, shows a removable progress toast, retries exactly once on 419 with the fresh CSRF token, applies a 30-second timeout, restores all PDP buttons on failure, and sends Buy now to `/checkout`.
- `shop.js` uses `data-variant-id`, updates every PDP add button, and preselects the first in-stock variant.
- `includes/account-layout.php` requires login before any account page logic runs; `CustomerRepository::eligibleReviews()` uses portable `ROW_NUMBER()`.
- Coupon removal is a real POST form with CSRF and `remove=1`; the newsletter error box is inside its form and wraps correctly in the flex layout.
- Added `tests/validate_bugfixes.py` and guest-account redirect checks in `tests/smoke.py`.

## Verification performed locally

- `bash tests/run.sh` — 187 PHP syntax checks, 3 JS syntax checks, 15 bug-fix static checks, 623 route/handler checks, JSON/Vercel readiness checks, and **73/0 HTTP smoke checks**.
- Real Chromium (390×844 mobile viewport) on a variant product: first variant preselected, cart badge changed from 0 to 1 within ~260 ms, success toast appeared, **0 console/page errors**.
- Real Chromium Buy now navigated to `/checkout`; coupon apply and remove worked through the real forms; newsletter error container was inside the form; guest wishlist redirected to `/login?next=…`.
- Clean ZIP rebuilt: 234 entries, 187 PHP files, integrity `ok`, `regions:["sin1"]`, no setup route/token literals/local secrets.
